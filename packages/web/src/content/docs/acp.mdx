OpenCode supports the [Agent Client Protocol](https://agentclientprotocol.com) or (ACP), allowing you to use it directly in compatible editors and IDEs.

:::tip
For a list of editors and tools that support ACP, check out the [ACP progress report](https://zed.dev/blog/acp-progress-report#available-now).
:::

ACP is an open protocol that standardizes communication between code editors and AI coding agents.

---

## Configure

To use OpenCode via ACP, configure your editor to run the `opencode acp` command.

The command starts OpenCode as an ACP-compatible subprocess that communicates with your editor over JSON-RPC via stdio.

Below are examples for popular editors that support ACP.

---

### Zed

Add to your [Zed](https://zed.dev) configuration (`~/.config/zed/settings.json`):

```json title="~/.config/zed/settings.json"
{
  "agent_servers": {
    "OpenCode": {
      "command": "opencode",
      "args": ["acp"]
    }
  }
}
```

To open it, use the `agent: new thread` action in the **Command Palette**.

You can also bind a keyboard shortcut by editing your `keymap.json`:

```json title="keymap.json"
[
  {
    "bindings": {
      "cmd-alt-o": [
        "agent::NewExternalAgentThread",
        {
          "agent": {
            "custom": {
              "name": "OpenCode",
              "command": {
                "command": "opencode",
                "args": ["acp"]
              }
            }
          }
        }
      ]
    }
  }
]
```

---

### Avante.nvim

Add to your [Avante.nvim](https://github.com/yetone/avante.nvim) configuration:

```lua
{
  acp_providers = {
    ["opencode"] = {
      command = "opencode",
      args = { "acp" }
    }
  }
}
```

If you need to pass environment variables:

```lua {6-8}
{
  acp_providers = {
    ["opencode"] = {
      command = "opencode",
      args = { "acp" },
      env = {
        OPENCODE_API_KEY = os.getenv("OPENCODE_API_KEY")
      }
    }
  }
}
```

## Runtime Environment Variables

OpenCode supports runtime environment variables for dynamic configuration when using ACP. These can be set when starting the ACP server or passed through your editor configuration.

### Provider Configuration

Dynamically configure provider API URLs, keys, and models at runtime:

```bash
# Set provider base URL
export OPENCODE_PROVIDER_ANTHROPIC_BASE_URL="https://api.minimaxi.com/anthropic"

# Set provider API key
export OPENCODE_PROVIDER_ANTHROPIC_API_KEY="your-api-key"

# Set available models (JSON array)
export OPENCODE_PROVIDER_ANTHROPIC_MODELS='["model1", "model2"]'
```

Environment variable format: `OPENCODE_PROVIDER_{PROVIDER_ID}_{CONFIG_KEY}`

### Prompt Customization

Override system and user prompts at runtime:

```bash
# Replace system prompt (supports file paths or direct text)
export OPENCODE_SYSTEM_PROMPT="file:///path/to/custom-prompt.txt"
# Or use direct text:
export OPENCODE_SYSTEM_PROMPT="You are a helpful assistant..."

# Add prefix/suffix to user prompts
export OPENCODE_USER_PROMPT_PREFIX="[Context] "
export OPENCODE_USER_PROMPT_SUFFIX=" [End Context]"
```

### MCP Tool Control

Control which MCP tools are enabled/disabled per session:

```bash
# Enable specific MCP tools (comma-separated)
export OPENCODE_MCP_ENABLED="browser,github"

# Disable specific MCP tools (comma-separated)
export OPENCODE_MCP_DISABLED="filesystem,database"
```

### Browser MCP

The built-in Browser MCP tool is automatically enabled. You can configure it:

```bash
# Disable Browser MCP
export OPENCODE_BROWSER_MCP_DISABLED="true"

# Custom Browser MCP command
export OPENCODE_BROWSER_MCP_COMMAND="npx -y @chrome-devtools/mcp"

# Browser MCP environment variables (JSON format)
export OPENCODE_BROWSER_MCP_ENV='{"CHROME_PATH": "/path/to/chrome"}'
```

## Support

OpenCode works the same via ACP as it does in the terminal. All features are supported:

:::note
Some built-in slash commands like `/undo` and `/redo` are currently unsupported.
:::

- Built-in tools (file operations, terminal commands, etc.)
- Custom tools and slash commands
- MCP servers configured in your OpenCode config
- Built-in Browser MCP tool (automatically enabled)
- Project-specific rules from `AGENTS.md`
- Custom formatters and linters
- Agents and permissions system
- Runtime environment variable configuration
